- Termo **engenharia de software** surgiu quando as aplicações foram ficando maiores e mais complexos, aparecendo muitos problemas
## Definição:
- Área da Computação destinada a investigar os desafios e propor soluções que permitam desenvolver sistemas de software - principalmente aqueles **mais complexos e de maior tamanho** - de **forma produtiva e com qualidade**.
- Não existe software livre de problemas práticos, mas há como mitigar eles
## Motivo: Dificuldades Essenciais
- Complexidade
- Conformidade
- Facilidade de Mudanças
- Invisibilidade
## Testes de Software
- Verificam se um programa apresenta um resultado esperado ao ser executado com casos de teste
- Podem ser
	- Manuais
	- Automatizados
- "Teste de software mostram a presença de bugs, mas não sua ausência" - Edsger W. Dijkstra
- Existem diversos tipos:
	- **Teste de unidade**(testar uma parte menor do código)
	- Teste de integração
	- Teste de performance
	- Teste de usabilidade
- Defeito: Funciona mas dá a resposta errado
- Bug: termo mais informal com sinônimo de defeito
- Falha: É o que acontece quando um código com defeito é rodado
- Todo software é testado, a questão é se quem testa é o usuário ou o programador
## Gerência de Configuração
- Todo software é desenvolvido usando um sistema de controle de versão
- Atua como uma "fonte da verdade" sobre o código
- Permite recuperar versões antigas
- Permite ver quem fez o que e quando fez
## Processos de Desenvolvimento de Software
- Processo de software: define as atividades que devem ser seguidas para construir um sistemas de software
- Dois principais modelos:
	- Waterfall("cascata"):
		- Inspirado no modelo de engenharia tradicional
		- Problema é que um software não é um carro, o modo tem que ser adaptado
		- Demora muito pra fazer teste, o que pode acabar ignorando erro em requisitos no começo
		- Insustentável para software
	- Métodos Ágeis:
		- Profundo impacto na indústria de software
		- Procura fazer tudo a todo tempo, não encascatar
